Together

The design system team defines what a Button is. Decree blocks any pull request — from a person or an AI agent — that uses a Button the definition does not permit.

Nathan — Specs 2

Defines the Harbor Button as a structured spec: primary | secondary, three sizes, secondary + lg is illegal, Ghost is retired. Anatomy and default styles stay in the spec — Decree never reads them.

demos/together/nathan/specs.yaml

TJ — DS Contracts

Defines the same Button as a machine-readable contract: the same props plus Figma and code bindings, and the fact that it renders a real <button>. Bindings stay in the contract — Decree never reads them.

demos/together/tj/contracts/button.contract.json

Decree — enforcement

Compiles both files down to the rules it can check in app code — component names, props, allowed values, illegal combinations, tokens, retirements — and fails CI when a change breaks them. It is not a spec tool, a Figma tool, or a code generator.

decree prepare --from-specs nathan --from-ds-contracts tj

The situation

  1. Harbor is a fictional design system, invented for this demo.
  2. A clean app builds its checkout page with variant="primary" and size="md". Verify passes.
  3. A dirty app — the kind of code an unsupervised agent produces — uses a ghost variant that does not exist, the illegal secondary + lg combination, an inline style=, the retired Ghost, an invented MagicButton, and a raw <button>. Verify fails with a named error code for each.
  4. The spec and contract files here are modeled on Nathan's and TJ's public work — the shape Decree wants to consume, ready to bind to real exports.

What refusal looks like

Real output from decree verify on the dirty app — a named, stable error code per violation, with file and line: 

DECREE_INVALID_PROP_VALUE    App.tsx:5   Invalid prop variant="ghost" on <Button> — allowed: primary, secondary
DECREE_INVALID_PROP_COMBO    App.tsx:6   Forbidden prop combination on <Button> — variant="secondary", size="lg"
DECREE_RESTYLE_STYLE         App.tsx:9   Restyle of <Button> via style= — use a contract variant or token instead
DECREE_DEPRECATED_COMPONENT  App.tsx:12  Deprecated component <Ghost> — use <Button> instead (Deprecated in Specs)
DECREE_UNKNOWN_COMPONENT     App.tsx:13  Unknown component <MagicButton> — not in the Decree contract allowlist
DECREE_NATIVE_ELEMENT        App.tsx:14  Native <button> used — use allowlisted <Button> instead

Agents ask first

The same contract also runs as an MCP server. An AI agent can list what the system permits and have a snippet refused before it writes code — <Button variant="ghost"> never makes it into the pull request. 

decree mcp decree.contract.json
